# Testbed v1.5.0 alignment + true 1:1 run engine — design & plan

**Date:** 2026-05-28
**Goal:** `azimuth-testbed.netlify.app` lets an external visitor (with their own API key, as now) run AZIMUTH **1:1** against their own input; the prestaged Boeing case-study is rebuilt; all changes align to **v1.5.0** of `github.com/MrBinnacle/azimuth`.

## Decisions (locked)
- **Run fidelity:** agentic file-loading loop — model loads reference files on demand via a tool, exactly like Claude Code.
- **Boeing rebuild:** re-run fresh against v1.5.0. Matrix = **Run 0 kept verbatim as labeled historical (Sonnet, pre-v1.5.0)** + fresh **Full / Thin / Adversarial** in clean context. The old contaminated-context run is dropped (not reproducible in a single stateless run).
- **Models:** update selector to current IDs — Opus 4.7 (`claude-opus-4-7`, default), Sonnet 4.6 (`claude-sonnet-4-6`), Haiku 4.5 (`claude-haiku-4-5-20251001`).
- **Generation:** runs are produced by a one-command Node script the **maintainer** runs with their own key (no key handled by the agent). Output committed as `prestaged-runs.json`.

## Hard constraints
- Netlify builds from the `azimuth-launch-kit` repo only — it cannot read the sibling `azimuth` repo. ⇒ skill files must be **vendored** (snapshotted + committed) into the testbed.
- Zero-telemetry posture; CSP `connect-src https://api.anthropic.com` already covers the multi-turn loop (no CSP change). Files are in-bundle (no network).
- Key never touches the agent; never committed.
- Model output is untrusted → render as text node only (keep existing `<pre>`, no `dangerouslySetInnerHTML`).

## Architecture
**Shared engine** `testbed/azimuth-engine.js` (pure JS, no React/DOM):
- `runAzimuth({ apiKey, model, prompt, skillBundle, maxTokens=8000, maxIterations=16, signal, onProgress, fetchImpl })`
- System prompt = `skillBundle.files['SKILL.md']` + minimal **runtime-harness suffix** (declares `read_file`/`list_files`, says referenced relative paths resolve through them).
- Tools: `read_file({path})` → dict lookup in `skillBundle.files` (normalize leading `./`,`/`; on miss return `ERROR: not found … Available: …`); `list_files()` → sorted paths.
- Loop: POST `/v1/messages`; while `stop_reason === 'tool_use'`, resolve tool_use blocks → append assistant + user(tool_result) → re-POST; stop on end_turn or iteration cap.
- Headers: `x-api-key`, `anthropic-version: 2023-06-01`, `anthropic-dangerous-direct-browser-access: true`, `content-type`.
- **Prompt caching:** `cache_control: ephemeral` on last system block, last tool, and rolling on the most recent message content block (≤4 breakpoints) to cut multi-turn cost.
- Returns `{ output, model, toolCalls: [paths], iterations, stoppedReason }`.

**Vendored snapshot** `testbed/skill-bundle.json` = `{ version, sourceCommit, generatedAt, files: {relPath: content} }` for the 26 runtime files (`SKILL.md`, `BEHAVIOR_SPEC.md`, `gotchas.md`, `references/*`, `diagnostics/*`, `domain-policies/*`). JSON (not JS) to avoid escaping markdown. Imported by both app and generator.

**Maintainer scripts** (`testbed/scripts/`):
- `bundle-skill.mjs` — reads the 26 files from `$AZIMUTH_REPO` (default `../../azimuth` rel to script, i.e. repo root sibling) at current HEAD, writes `skill-bundle.json` with version (CHANGELOG top entry) + `git rev-parse HEAD`. Agent runs this now (azimuth repo is local); output committed.
- `generate-boeing-runs.mjs` — imports `azimuth-engine` + `skill-bundle.json` + shared `constants.js`; runs Full/Thin/Adversarial via `runAzimuth`; writes `prestaged-runs.json` (the 3 fresh runs with extracted verdict/confidence). Maintainer runs with `ANTHROPIC_API_KEY`.

**Shared constants** `testbed/constants.js` — `PROMPT_VARIANTS`, `MODELS`, `ALL_TAGS` (used by app + generator).

**App** `testbed/App.jsx`:
- Replace single `fetch` in `handleRun` with `runAzimuth(...)`; surface `onProgress` as live loop status (e.g. "Loaded references/module-guide.md").
- Initial runs = fresh runs from `prestaged-runs.json` (Full/Thin/Adversarial) + `RUN_0` historical anchor (kept). App handles empty/missing `prestaged-runs.json` gracefully (shows Run 0 only) so it builds before generation.
- Update `MODELS`, default model.
- Copy: version markers `pre-v1.4.0`→`pre-v1.5.0`; remove stale `P1.2/P1.5` placeholders; fix banner referencing runs that weren't loaded; reflect current model.
- Remove the now-stale embedded `AZIMUTH_SYSTEM_PROMPT` (engine uses bundle) and embedded `RUN_0_OUTPUT` if moved to a static module.

## Tests / verification
- `npm test` (vitest) green incl. new engine tests with mocked Anthropic responses (single-turn, multi-turn tool_use, missing-file, iteration cap, abort).
- `npm run build` succeeds.
- Dev server renders; a mocked run completes and logs.
- Manual live run is gated on a real key (maintainer).

## Handoff steps (require maintainer key / deploy auth)
1. `cd testbed && ANTHROPIC_API_KEY=sk-ant-… node scripts/generate-boeing-runs.mjs` → commit `prestaged-runs.json`.
2. Verify a live self-serve run in the browser with a real key.
3. Deploy: `netlify deploy --prod` from `azimuth-launch-kit/` (testbed prod is local-CLI, NOT git-auto-deploy).

## Out of scope
- Contaminated-context demonstration run.
- Telemetry / trace-ID banner.
- Any change to the `azimuth` skill repo itself.
